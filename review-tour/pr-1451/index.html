Wiring tests set the board's state, not the rule

1 stop0 questions61 of 379 changed lines on the tour

The problem

To check that Investigate turns off under Locked Door, or that a move shows two arrows under Frozen in Fear, web tests built the treachery with its restriction or modifier. That re-tested the engine's rules in every web test that needed the state, and a rule change broke component tests that only check wiring.

What changes

A test helper wraps the real board and replaces only the answers a test names: boardWhere for any member (an action cost, an enemy's card effects), locationWhere and investigatorWhere for a field of one location's or investigator's view wherever the board lists it (forbidden, shroud). Steps the test plays still go to the real table. The rewritten tests are tables per control kind.

How we know it works

  • Every rewritten test depends on its override: with boardWhere ignoring the answers, all 9 fail.

    pnpm vitest run apps/web  # 1233 passed

  • The dropped rule tests are covered in the engine: Frozen in Fear in action_costs.test.ts, massive enemies in board_view.test.ts.

    pnpm test

That's the whole change.
