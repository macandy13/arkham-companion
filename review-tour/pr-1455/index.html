Spending an action is its own command and event

4 stops1 question61 of 258 changed lines on the tour

The problem

Spending an action looked exactly like a correction of the action count, so nothing could react to an action being spent or tell the two apart in the log.

What changes

The engine pays for an action with SpendActions, whose ActionsSpent event names what was paid for; AdjustActions is only for corrections and card grants.

Question for you

  1. Logs saved before this change hold payments as ActionsAdjusted with a for the reducer now ignores, so a game reloaded mid-round would charge Frozen in Fear's first move again. Is that acceptable while saved games need no backward compatibility?
