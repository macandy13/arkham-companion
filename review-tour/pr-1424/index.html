Resolutions read the ability condition

3 stops0 questions83 of 404 changed lines on the tour

The problem

A scenario's resolutions asked about the ended game in a third condition language (GameCondition: a card in some places, N cards of a trait, the current agenda), next to the one abilities and card actions read. It repeated currentCard and countOf under other names, and a resolution couldn't ask anything else an ability can.

What changes

Resolution steps now take an AbilityCondition, read on the ended game's table outside any timing window: there a reference to the window's card or investigator names nothing, and only what the table answers by itself (the lead, the only copy of a card) stands for something. Where a card lies is the references abilities already use (eachInZone, eachInPlay), so GameCondition and its place list go, and "beneath the act" names the act by its only copy, which still finds it once it advanced out of the game.
