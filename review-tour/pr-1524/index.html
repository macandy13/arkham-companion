Daily digest workflow

3 stops1 question68 of 115 changed lines on the tour

The problem

The digest renderer exists, but nothing runs it, so the owner has no daily page of what merged without them.

What changes

A scheduled workflow builds one NDJSON line per merged PR: its body, reviews, the gate status on its head, and the patches of its rules pages. It runs the digest CLI, publishes the page at digest/<date>/ and digest/, and comments on the digest issue only on days with entries.

Question for you

  1. Comment daily on one pinned issue, or open an issue per day?

    Concerns stop 3. Picked: One issue with a comment per day that has entries: one notification, one place to scroll back, and quiet days post nothing..

A fixed window

The search takes merges from 05:00 UTC yesterday to 05:00 today, so the days join up even when the schedule starts the run late. Only the rules pages' patches are kept, which keeps a huge diff from breaking the job.

One comment on the digest issue

The first run creates the issue labelled digest for the owner to pin. After that, each day with entries adds one comment with the link and the count.
