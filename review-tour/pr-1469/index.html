Basic action tests carry their results in the options

4 stops0 questions65 of 475 changed lines on the tour

The problem

A card's skill test carries what each outcome does in its options, as data, but the basic actions' tests did not: investigate, fight and evade left their options empty and worked out the clues, damage and evasion in code when the answer arrived (testedActionCommands, keyed by a field only they had, Decision.testKind). Two paths for one thing, and the second one the outcomes-as-data rule rules out.

What changes

The basic actions now raise their test the way a card does: the pass option holds the discovery, the damage or the evasion, its confirmed count written { answer: 'amount' }, the fail option a failed attack's redirect, and each outcome ends with EndSkillTest. The test names its action (SkillTest.action). The commands read the table as the answer arrives, so corrections made while the test was open still count, as before.
