Show a refactor's usage before and now

2 stops0 questions15 of 58 changed lines on the tour

The problem

A refactor or an API change is easiest to judge by how the code that uses it changes. The review page could show one code example per claim, so a tour could show the new usage but not what it replaces.

What changes

A piece of evidence can now give the old usage in before next to its example. The page shows them one above the other as "Before" and "Now". The coding guidelines ask every refactor and API change to include one such pair, kept narrow enough for a phone.

1Page

Before and Now on the page

With a before, the example shows the old usage above the new one, each with a small label. Without one, it looks as it did.
