Play-tester smoke run on PRs

2 stops2 questions43 of 57 changed lines on the tour

The problem

The play tester only ran at night, so a rule bug that shows up only when cards interact could merge without the owner and surface the next morning, after other PRs had built on it.

What changes

A CI job plays 100 seeded games (46 seconds locally) on every PR that touches the engine, scenarios, card data, the play tester, util or the dependencies, and replays the committed records of fixed bugs. Other PRs pass the job at once, since a required check has to report on every PR.

Questions for you

  1. Fixed seed or a fresh one per PR?

    Concerns stop 1. Picked: Fixed (seed 1): main passes it, so a finding is always the PR's own and a re-run gives the same games. The nightly run keeps exploring fresh seeds..

  2. Should the gate read the smoke result, or should the ruleset require it as a check?

    Concerns stop 2. Picked: The ruleset requires it next to gate and the other CI checks. The gate never reads check results, because CI already blocks a red PR, and reading them would need another workflow_run trigger..

The smoke job

The job diffs the PR's merge commit against its first parent, the base. It installs and plays only when code a game runs on changed. On a finding it keeps the records as an artifact for 14 days.
