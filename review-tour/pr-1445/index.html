The engine pays action costs

2 stops2 questions52 of 533 changed lines on the tour

The problem

The engine left counting actions to the players: every caller that took an action had to spend it first (the screen's taking() wrapper, the play tester's countOffAction, PlayTable.spendActionFor in each scenario story), and a caller that forgot, like the end-to-end stories with Frozen in Fear, silently played with too many actions.

What changes

An action command taken asAction now pays what it costs before handle runs it: actionPayment turns it into one AdjustActions (its actionCost, named for the round's first, as Frozen in Fear needs), one action for a card ability with the action symbol, none for a [free] one. asAction: 'free' is a move, fight or evade a card lets you take: it pays only what cards add and provokes nothing. Only the player's own command pays, so an action held for attacks of opportunity doesn't pay again when it resumes.

Questions for you

  1. A free move that Frozen in Fear raises to 1 action still provokes no attack of opportunity, as the free buttons did before. The Rules Reference exempts [free] abilities; no ruling covers a raised one, so the rules page notes it as our reading. Keep it?

    Concerns stop 2.

  2. The Devourer Below story had never paid Frozen in Fear's extra action. With the engine counting, Daisy's round 5 turn is one action short; the story grants it by hand with a comment rather than rewriting the later rounds. Fine, or should the story be replayed with one action fewer?
