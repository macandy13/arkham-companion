Test each claim once, in the layer that owns it

3 stops0 questions12 of 37 changed lines on the tour

The problem

Tests are about as long as the production code (~63k lines). A rule like Dissonant Voices is tested in the engine and again in the investigator bar, scenario tests restate card data, and The Gathering's end-to-end test is 1,413 lines because every rule PR has to add a step to it.

What changes

Each kind of claim gets one owning layer: the engine owns rules, scenario tests own what a card adds, web tests own wiring, E2E owns journeys and looks, the play tester owns integration. End-to-end steps are only for rules that change how a whole game plays. The review guide and the test-writer agent check the same list.

End-to-end steps only for whole-game rules

Replaces the rule that every rule PR extends an end-to-end test; other rules rely on unit tests and the nightly play tester.

66−- **A new or changed rule shows up at the table.** Every PR that adds or changes a game rule extends an end-to-end scenario test with a step where the rule happens in play, and links that step next to the rules claims in the PR description's folded "Everything else" box. Rule gaps are easiest to spot in a playthrough, not in unit tests of the rule alone.75+- **A rule that changes how a whole game plays shows up at the table.** A new phase step, a new way to reach a resolution or a new kind of turn gets a step in an end-to-end scenario test, linked next to the rules claims in the PR description's folded "Everything else" box. Every other rule is covered by its unit tests and the play tester.
