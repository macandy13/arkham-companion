Every rules claim names its test

3 stops1 question51 of 208 changed lines on the tour

The problem

When rule code merges without the owner reading it, nobody can see which rules the app actually enforces or which test checks them. The rules pages describe the rules, but nothing ties a claim to code, and a test can be renamed or deleted without anyone noticing that the claim lost its proof.

What changes

Each claim on a rules page gets one line per test that proves it, written as the test file followed by its describe and it titles. A small checker reads those lines from every page and fails the unit test suite when a named test no longer exists. The rules checker now lists these lines for every claim it confirms, so the session adds them in the same PR.

Question for you

  1. Check the named tests by reading the source, or by running the suite and comparing its list of test names?

    Concerns stop 2. Picked: Reading the source: it is fast and runs inside the normal unit tests. The cost is that a title built with ${…} can't be named; running the suite would handle that but needs a separate step in CI..

2API

The checker matches titles as test calls, in order

A title only counts where it is the first argument of a describe, it or test call, so the same words in a command literal or an assertion don't keep a deleted test alive. The titles must appear in the given order, so a test moved under another describe fails too.
